# CODEX TASK 001 — первый проверяемый Windows-релиз «Фотоархива»

## Вход
Пользователь передаёт ZIP `Fotoarhiv_Codex_Handoff_v0_2.zip`, внутри существующий проект `Fotoarhiv.slnx`, C# / WPF / .NET 10, SQLite, MetadataExtractor, xUnit, workflow Windows CI. Перед началом прочитай `AGENTS.md`, `README_RU.md`, `INSTRUCTIONS_CHATGPT_PROJECT.md`, затем относящийся к работе код. Не начинай проект заново и не меняй стек.

## Доступ и ограничения
Доступ ChatGPT к GitHub пользователя только для чтения. Работай с загруженными исходниками или локальной рабочей копией. **Не рассчитывай, что можешь выполнить push, коммит в удалённый репозиторий или создать PR.** Сохраняй все изменения в результирующем архиве. Если доступна самостоятельная локальная сборка на Windows — используй её. Если нет, настрой GitHub Actions и честно укажи, какие проверки остались неподтверждёнными. Не требуй от пользователя терминала.

## Цель P0 (один ограниченный этап)
Получить компилируемую, запускаемую на Windows 11 x64 и протестированную **неразрушающую** версию v0.2.x. Не вводить функции удаления, перемещения, создания копий архива, визуальных дублей, встроенной карты и глобального редизайна.

## Шаги
1. Проверить структуру solution, все csproj, зависимости NuGet, WPF XAML/code-behind и workflow `.github/workflows/build-windows.yml`. Обнаружить и исправить фактические ошибки компиляции, публикации или запуска. При дефекте добавлять тест, если его можно автоматизировать.
2. Выполнить restore, Release build, xUnit тесты и publish на Windows. Публикация — self-contained win-x64, без VBS, `.ps1`, `.cmd` для запуска и обхода политики безопасности. Если single-file вызывает проблемы, разрешено публиковать папку из нескольких файлов с одним основным `Fotoarhiv.exe`; объяснить причину. В CI создать ZIP артефакт исполняемого приложения (и отдельно результаты тестов при необходимости).
3. Проверить и исправить при необходимости: добавление одной/нескольких папок; обход подпапок; сохранение SQLite-каталога между запусками; корректная дата съёмки или маркированная дата файла; GPS только из метаданных; группировка полных дублей по SHA-256; повторное сканирование без потери хеша; сохранение сведений об отключённых накопителях; поиск, фильтр по году, страничная галерея и отмена сканирования.
4. Добавить или уточнить автотесты критических сценариев: одинаковые файлы под разными именами; файлы равного размера с разным содержимым; файл изменился — прежний хеш нельзя использовать; файл без EXIF; корректная EXIF-дата; GPS из валидного образца; недоступная папка; отмена сканирования; стабильность повторного сканирования; исходные байты и времена не изменяются. Используй в тестах маленькие локальные искусственные изображения; не включай настоящие пользовательские фотографии.
5. Устранить блокирующие UX-дефекты (кнопки, некорректные сообщения об ошибке, блокировка интерфейса при обработке), не расширяя объём задачи до полного редизайна. Если сценарий пока не реализован (например, «Собрать архив»), оставь честную заглушку, а не имитацию выполнения.
6. Проверить результат на тестовом наборе и зафиксировать результат. Если реальный GUI-тест на Windows недоступен, отдельно написать, что проверены только сборка/автотесты и что нужно проверить вручную.

## Критерии завершения
- Windows x64 publish успешно создан, тесты проходят, приложение запускается хотя бы в проверяемой Windows-среде; иначе задача **не завершена**, а проблема и следующий шаг описаны.
- При индексации исходные фото физически не изменяются; не присутствуют операции удаления/переноса/переименования.
- Срабатывание антивируса не «лечится» выключением защиты или добавлением исключений. Если неподписанная сборка вызывает SmartScreen, указать ограничение, не давать инструкций по обходу.
- Нет «ложно работающих» кнопок; геолокация и даты корректно помечают источник.
- CI workflow успешно выполняется или есть конкретная исправляемая причина, почему он не выполнялся.
