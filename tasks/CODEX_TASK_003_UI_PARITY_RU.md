# Фотоархив — CODEX_TASK_003: восстановить утверждённый интерфейс по HTML-эталону

**Статус:** новое задание, реализация ещё не выполнена.  
**Источник:** действующий репозиторий `kqh2rnnnmm-dot/Fotoarhiv`, ветка `main`, существующий WPF/.NET проект v0.2.1.  
**Авторитетный UI-эталон:** `UI_REFERENCE/Фотоархив — прототип.html` и 4 PNG в `UI_REFERENCE/`. Именно этот внешний вид пользователь ранее выбрал и сейчас повторно подтвердил. **Не ориентироваться на случайный пересказ дизайна, прежде всего открыть сам HTML и скриншоты.**  
**Цель:** максимально близко перенести визуальную систему эталона в *нативное* Windows-приложение, сохранить существующую работающую логику и честно отразить недоступные функции.

## 0. Важные контексты

- Пользователь не программист. Основной компьютер — **Windows 10 x64** (уточнено после первых сборок); нужна также совместимость с Windows 11 x64. Официальную поддержку выбранного runtime на конкретной редакции Windows проверять отдельно; не выдавать тест на Windows Server за тест на компьютере пользователя.
- После v0.1 на VBS/PowerShell пользователь столкнулся с реакцией антивируса. Ни в исходниках, ни в опубликованном пакете **не должно быть VBS/PS1/CMD/BAT запускателей, обхода SmartScreen, отключения защиты или просьбы добавить исключение**. .exe может быть неподписан: честно описать это.
- GitHub `kqh2rnnnmm-dot/Fotoarhiv` доступен для чтения и, по последней проверке, для записи. Прежде чем делать commit/push, проверь текущие права и явное разрешение пользователя на этот репозиторий. Не применять разрешение к другим репозиториям. При любом исходе вернуть полный ZIP исходников, отчёт и проверенную сборку при наличии.
- Источник правды об архитектуре и безопасном режиме — `AGENTS.md`, исходники `src/Fotoarhiv.App` и `src/Fotoarhiv.Core`, тесты; не создавать новое приложение с нуля.

4. Проверить текущий код/UX-пропуски. Составить перечень расхождений до редактирования.

## 2. Обязательная визуальная система

Перенести UI средствами WPF/XAML (допустимы аккуратные ресурсы/стили и минимальная перестройка UI). **Не заменять приложение веб-страницей в WebView** и не вводить обязательный интернет для отображения интерфейса.

- Фон рабочей области светлый `#F6F7F9`, основные карточки белые, текст близок к `#1A2636`, вторичный `#798494`, разделители `#E7EBF1`, активный синий примерно `#3368F0`; типографика Segoe UI, мягкие скругления, умеренные отступы.
- Слева **белая** панель шириной около 232 px (в эталоне), бренд `фотоархив.` с синей точкой. Пункты «Фотографии», «Карта», «Повторы», «Альбомы», «Источники»; активный пункт — светло-синий с синей меткой, а не сплошная тёмная панель.
- Верхняя **белая** панель высотой ~87 px: поиск, «Добавить папку», синяя основная кнопка «Собрать архив». Контролы с фокусом с клавиатуры.
- Экран «Фотографии»: крупный заголовок, короткое пояснение, правый ненавязчивый бейдж безопасности, 4 карточки показателей **из реальных данных** (число фото, точных повторов, мест съёмки, источников), фильтры годов; лента группируется по **годам/месяцам съёмки**, фотографии сеткой с закруглёнными углами и нижним градиентом подписи (дата/место только если подтверждены). Для неподтверждённой даты показывать «Дата файла»; не выдумывать географию.
- Экран «Карта»: та же оболочка, чёткое место для карты и правая колонка мест; **если встроенной карты пока нет**, разместить честное пустое состояние «Интерактивная карта появится позже», оставить работающий список GPS и явное открытие координат в браузере по действию пользователя. Нельзя показывать нарисованные демонстрационные города или точки как настоящие; координаты никуда не отправлять без действия.
- Экран «Повторы»: белые карточки с реальными превью и сопоставлением, фильтр «Точные копии» рабочий; категории «Разные версии» и «Похожие кадры» обозначить как будущие, а не рассчитывать фиктивные группы. Реальные точные дубли определяются SHA-256 содержимого и совпадением размера. Никаких действий удаления.
- Экран «Альбомы»: сохранить навигацию и визуальный язык; до настоящей реализации — понятное пустое состояние, не ложные «Поездка в Сочи» или фиктивные числа.
- Экран «Источники»: белые карточки папок, доступность/недоступность с читаемыми индикаторами, количество известных снимков только при наличии данных.
- Клик по фото: **выдвижная правая карточка** с настоящим превью, именем, EXIF/датой файла, разрешением (если известно), размером, источником, GPS (если подтверждён) и доступностью. Отсутствующие сведения не подменять вымышленными. Закрытие крестиком/Escape.
- «Собрать архив»: стилистика модального окна эталона с двумя вариантами **«Создать копии» и «Переместить»**, предварительной структурой. Но на текущем этапе **НЕ реализовывать файловые операции** и **не показывать ложный рассчитанный план**: уместно отобразить их как «В разработке», с отключённой кнопкой запуска и ясным текстом. Ни одна кнопка не должна создавать/удалять/перемещать оригиналы.
- В прототипе демонстрационные картинки и цифры. **Не переносить их как реальные пользовательские данные**. Допускается использовать искусственные тестовые изображения исключительно в детерминированном UI-тесте/скриншоте, никогда по умолчанию внутри пользовательского каталога.

## 3. Интерактивность и короткие сценарии

- При первом запуске пустой каталог, понятное приглашение «Добавить папку» (без лишнего wizard). Добавление через стандартное окно выбора папок.
- Основной пользовательский путь: запуск → добавить папку → видеть реальную ленту; поиск, фильтр года, переходы «Фотографии/Повторы/Карта/Источники» без лишних окон.
- Найти снимок по имени/пути (пока нет поиска по месту — не обещать в placeholder поиск по месту); детали фото в панели, без модального MessageBox с текстом.
- Скролл/подгрузка на больших коллекциях не должны резко блокировать UI. Не загружать тысячи полноразмерных фото в память. Записи недоступных дисков остаются в каталоге; превью офлайн ещё не кешируются — не обещать обратного.
- Клавиатура: Tab/Enter/Escape, видимый фокус, читаемый контраст, названия кнопок доступны экранным читалкам.
- Результат должен корректно выглядеть на 1366×768, 1440×900, 1920×1080, 125% и 150% масштабах Windows. При узком окне допустима адаптация числа колонок, без горизонтального обрезания действий и диалогов.

## 4. Строгие границы

- Сохранять `Fotoarhiv`, `Fotoarhiv.slnx`, имена классов, каталог SQLite, существующие сервисы и базовую структуру проекта.
- Не переписывать сканер/SQLite/EXIF/GPS/SHA-256 без доказанного дефекта; не включать новую логику распознавания схожих фото, геокодер, реальный механизм сборки архива или удаление.
- Не писать в исходные изображения при просмотре/сканировании.
- Новые UI-зависимости — только при реальной необходимости, с обоснованием лицензий/офлайн-работы. Предпочесть WPF ResourceDictionary, штатные элементы и шаблоны.
- Не менять даты/координаты ради красивого экрана, не показывать «всё готово» при ошибках/отмене.

## 5. Разработка и тестирование

1. До реализации написать/обновить тесты ожидаемого поведения UI, безопасных пустых состояний и моделей, желательно сначала воспроизвести существующие несоответствия.
2. Выполнить минимальную UI-реализацию с WPF ресурсами/стилями; существующие unit-тесты должны оставаться зелёными.
3. Собрать Release под win-x64; запустить xUnit; отдельно запустить проверку реального окна и автоматизированные GUI-сценарии. Не объявлять PASS, если тест только написан и не запускался.
4. Снять собственные скриншоты **на реальном WPF приложении**: фотографическая лента, точные повторы, GPS-панель/пустое состояние карты, окно архива/заглушка, подробности фото, источники. Использовать детерминированные искусственные файлы; проверить их подлинность по сравнению со скриншотами HTML, письменно перечислить оставшиеся визуальные расхождения.
5. Проверить, что источник не меняется: имена, содержимое/хеш, расположение, дата создания/изменения. Проверить поиск, годы, повторный запуск, отмену, недоступный диск (что реально доступно в среде).
6. Отдельно подтвердить поведение на Windows 10 x64 (желательно 22H2, с фиксированной редакцией/билдом) и Windows 11 x64. Если нет таких сред, явно отметить NOT RUN; Windows Server CI **не приравнивать** к персональной Windows 10/11.
7. Не выпускать ZIP Windows-сборки, если обязательная компиляция/тесты упали. Проверить, что publish содержит весь набор DLL рядом с exe и нет запрещённых launch-скриптов.

## 6. Критерии приёмки

- Открытие приложения визуально узнаваемо как исходный светлый HTML-эталон, а не предыдущий тёмный WPF экран.
- Топбар, белое меню слева, цветовая палитра, месячная хронология и фото-плитки выполнены в соответствии со скриншотами.
- Реальные снимки отображаются; поиск/год/точные повторы/источники/GPS работают не хуже v0.2.1.
- Клик на фото открывает боковую карточку, не MessageBox; данные подлинные.
- Не реализованные категории и операции не создают видимость готового результата; никакого изменения исходников.
- Никаких критических ошибок запуска, обрезанных контролов и ложных метрик.
- Протокол тестов и фото реального работающего интерфейса подтверждают результат.
