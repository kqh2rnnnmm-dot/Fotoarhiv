# Фотоархив — версия 0.2.1, исходный проект C#/.NET (тестовая)

## Главное

Это **исходники**, а не готовая установочная программа. Проект рассчитан на Windows 11 x64.
Прежняя версия с VBS/PowerShell больше не используется; запускать её не надо.
В новой версии нет файлов VBS/PS1/CMD и нет команды обхода политик безопасности.

ZIP с Windows-приложением не предоставлен. Первый этап передачи выполнялся архивами; теперь пользователь разрешил загрузку исходников в GitHub. Статус нового Windows run фиксируется отдельно по его фактическому результату.
Подробности Task 002 — в `BUILD_REPORT_RU.md` и `verification/task002/`.

Исправлены ошибки компиляции GPS/WPF, проверка актуальности сохранённых хешей и отмена.
При недоступном источнике выводится сообщение о неполной проверке, записи сохраняются.
Общий дизайн, C#/.NET/WPF, SQLite и структура решения сохранены.

Существующие возможности кода (GUI-сценарии ещё требуют проверки на Windows):

- Обычное Windows-окно на WPF (.NET 10), список и миниатюры фотографий, поиск по пути/имени и фильтр по году.
- Добавление источников через стандартное окно выбора папки, сканирование подпапок.
- SQLite-каталог `%LOCALAPPDATA%\Fotoarhiv\catalog.sqlite`.
- Дата съёмки из EXIF, если доступна; иначе дата изменения файла с явной пометкой «Дата файла».
- GPS-координаты EXIF, если есть; открытие точки в браузере на OpenStreetMap.
- Поиск точных копий по SHA-256 (только одинаковое содержимое).
- Записи об отключённых внешних дисках остаются в каталоге.
- Отмена сканирования. Повторное сканирование использует сведения о неизменённых файлах.

Важные ограничения:

- Это **не проверенный Windows-релиз**. Компиляция и автотесты выполнены на Linux; Windows-сборка и GUI ещё не проверены.
- В этой версии НЕТ визуального распознавания похожих фото, интерактивной встроенной карты, создания копий архива, перемещения файлов, удаления и интеллектуального выбора лучшей версии. Кнопка «Собрать архив» показывает сообщение о будущем этапе.
- Для HEIC/RAW записи сохраняются, но миниатюры могут отсутствовать без соответствующего кодека Windows; даты и GPS зависят от поддержки формата библиотекой.
- Для очень больших коллекций (сотни тысяч файлов) ещё предстоит оптимизация фоновой загрузки миниатюр, индексации и переключения страниц.
- Проверка разрешений Windows/NTFS, диалога папок, поиска, фильтра по году, страниц, кодеков и отключения физического диска остаётся ручной. Windows workflow подготовлен, но в этой сессии не запускался.
- Кеш хеша проверяется по размеру и времени изменения. Изменение содержимого с сохранением обоих признаков не обнаруживается; изменение файла уже после проверки также возможно. Время последнего доступа может обновлять сама ОС при чтении; тесты проверяют байты, время записи и создания.
- Windows SmartScreen/антивирус могут предупредить и о новом неподписанном EXE. Не игнорировать предупреждение и не отключать защиту. Для массового выпуска понадобится цифровая подпись.

## Как получить .exe без ввода команд в терминал

Репозиторий создан: https://github.com/kqh2rnnnmm-dot/Fotoarhiv . При повторной проверке в main найден только README.md, запусков Actions — 0. В него необходимо загрузить содержимое этого ZIP, сохранив папку `.github/workflows/`.
При загрузке в ветку main/master GitHub Actions запускает сборку на Windows runner. Нужны права владельца на загрузку файлов; подключение ChatGPT только для чтения этого не делает. Workflow для `windows-2025` (Windows Server, не Windows 11) подготовлен для restore, Release build, xUnit, publish, запуска/закрытия окна и UI Automation. Он сохраняет логи, фактическую ОС, commit/run URL, TRX, снимки окна и SHA-256-манифест publish в артефакт `Fotoarhiv-Windows-test-results`. Подготовленные GUI-проверки охватывают добавление двух источников, подпапки, поиск, год, страницы, карточку EXIF, навигацию, дубли, повторный запуск и неизменность тестовых оригиналов. Выполнение этих проверок на Windows ещё не подтверждено. Он ещё не был выполнен для этой версии. Дальнейшие действия:

1. Откройте репозиторий GitHub и вкладку **Actions**.
2. Выберите **Build Fotoarhiv Windows x64** и **Run workflow** (если доступно).
3. Дождитесь окончания проверки. При **зелёном** статусе в разделе **Artifacts** скачайте `Fotoarhiv-Windows-x64-0.2.1-TEST`.
4. Распакуйте скачанный артефакт, затем вложенный `Fotoarhiv_Windows_x64_TEST.zip` в отдельную папку. Сохраните все файлы рядом с `Fotoarhiv.exe`. Это публикация папкой; отдельно установленный .NET не нужен.
5. Запускайте только после проверки результата сборки и предупреждений защиты; сначала тестируйте на небольшой копии данных.

Если Actions выдаёт ошибку, это означает, что выпуск блокируется, а не что нужно отключать антивирус.

## Структура исходников

- `src/Fotoarhiv.Core` — индексатор фотографий, чтение метаданных, сравнение SHA-256, SQLite.
- `src/Fotoarhiv.App` — окно WPF для Windows 11.
- `tests/Fotoarhiv.Tests` — тесты бездеструктивного сканирования, сохранения каталога, дублей и повторного сканирования.
- `.github/workflows/build-windows.yml` — Windows-сборка и тесты, без локальных скриптов запуска.

## Безопасность

Сканирование открывает пользовательские файлы только для чтения. База данных создаётся только в профиле пользователя; исходные фото не переносятся, не переименовываются, не удаляются. Предполагаемое физическое перемещение появится как отдельный модуль с предварительным просмотром и подтверждением после независимых тестов.
