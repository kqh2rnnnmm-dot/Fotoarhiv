## Цель продукта
Локальное настольное приложение «Фотоархив» для Windows 11 x64, которое объединяет фотографии из разных папок и дисков в единую интерактивную библиотеку, не трогая оригиналы при обычном просмотре. Поддержка хронологии по реальной дате съёмки, GPS-карты, групп точных дублей, версий одного снимка и похожих кадров. В дальнейшем — физическая сборка архива двумя независимыми способами: КОПИРОВАТЬ с сохранением источников или ПЕРЕМЕСТИТЬ с обновлением путей. Пользователь должен видеть и выбирать, что произойдёт.

## Неизменные правила
1. Сканирование и виртуальный каталог — строго без записи в исходные фото, их перемещения, удаления или переименования. Создавать служебную базу, миниатюры и журналы разрешено только в каталоге приложения.
2. До операции копирования/перемещения показать предварительный план: источники, назначения, возможные конфликты, объём и доступное пространство. После явного подтверждения выполнять пофайлово, с журналом и проверкой хеша копии. При сбоях не объявлять успех; никогда не удалять исходник, пока копия не проверена. Функции перемещения не добавлять до отдельного этапа и тестов.
3. Точные дубли — сравнение SHA-256 содержимого при совпадающем размере. Похожие фотографии — отдельная категория, не приравнивать их к дублям и не удалять автоматически.
4. Сохранять все уникальные фотографии. Для разных версий снимка не выбирать «лучшее» только по размеру файла: учитывать пиксели, формат, компрессию и доступные метаданные. Сомнительное оставлять на проверку пользователя.
5. Приоритет дат: реальные метаданные съёмки (EXIF и другие поддерживаемые источники); дата изменения файла — только маркированный резервный вариант. Не выдавать время копирования за время съёмки. Учитывать неоднозначность часовых поясов.
6. GPS показывать только из имеющихся подтверждённых метаданных либо по ручной установке пользователя; никогда не придумывать координаты. При отсутствии интернета библиотека остаётся работоспособной, карта может показывать ограниченные данные.
7. Отключённые диски не означают удалённые фотографии. Хранить карточки и миниатюры с пометкой «источник недоступен», не вычищать записи автоматически.
8. Локальная обработка данных по умолчанию: не отправлять фотографии, пути, GPS или миниатюры на сервер. Любые сетевые карты, обновления и аналитика — явные и объяснимые действия.
9. Никаких VBS/PowerShell-файлов запуска, обхода ExecutionPolicy, отключения антивируса либо требований добавлять приложение в исключения. Итог — Windows x64 .exe или штатный установщик, с честным описанием подписи/SmartScreen.
10. UX: современная, спокойная, быстрая программа в духе Windows 11. Первая страница — фотолента; основные разделы: «Фотографии», «Карта», «Повторы»; источники и «Собрать архив» доступны без длинной навигации. Один сценарий — минимум кликов. Технический прогресс и ошибки должны быть понятны без жаргона.
11. Не переименовывать проект, существующие классы/папки и публичные пользовательские обозначения без веской причины и согласования. Не переписывать всё ради косметики; соблюдать контрольные точки.

## Технология и состояние
Исходная база — C# / .NET 10 / WPF, SQLite, MetadataExtractor, xUnit. Версия приложения v0.2.1. Linux-компиляция WPF с Windows targeting и 18 xUnit-тестов подтверждены. Сканирование, EXIF/GPS, SQLite и SHA-256 пока НЕ подтверждены исполняемой сборкой на Windows; текущий этап — Task 002. Версию v0.1 на VBS/PowerShell не использовать. Встроенной карты, поиска визуально похожих снимков, физической сборки архива пока нет. Прежде чем расширять функции, добиться компиляции, зелёных тестов и работающего Windows x64 exe.

## Процесс разработки
Для каждой задачи: изучить текущие файлы и согласованные решения → коротко определить границы → сначала написать или скорректировать тесты → реализовать минимальные изменения → собрать и выполнить тесты → провести проверку главных пользовательских сценариев → выдать результат и контрольную точку. Для каждого результата разграничивать «написано», «скомпилировано», «протестировано», «проверено на Windows пользователем». Если тест не выполнен, указать почему и не выдавать задачу за полностью закрытую.

## Последовательность этапов
P0 — устранить ошибки и собрать первый работающий, неразрушающий Windows exe; P1 — миниатюры, хронология, отзывчивость и инкрементальное сканирование больших коллекций; P2 — визуально похожие изображения и сравнение версий без удаления; P3 — встроенная карта GPS и фильтры по месту/времени; P4 — отдельное копирование отсортированного архива с предварительным просмотром и проверкой; P5 — безопасное перемещение со сверкой, журналом, восстановлением после сбоя. Не смешивать этапы без необходимости.
