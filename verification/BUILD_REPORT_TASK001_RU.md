## Команды

Фактический исполняемый файл: `/tmp/fotoarhiv-dotnet/dotnet`; ниже для краткости `dotnet`.
Рабочая папка: `/workspace/Fotoarhiv`.

```text
dotnet --info
dotnet restore Fotoarhiv.slnx -p:EnableWindowsTargeting=true
dotnet build Fotoarhiv.slnx -c Release --no-restore -p:EnableWindowsTargeting=true
dotnet test tests/Fotoarhiv.Tests/Fotoarhiv.Tests.csproj -c Release --no-build --logger "trx;LogFileName=linux-tests.trx" --results-directory verification
dotnet publish src/Fotoarhiv.App/Fotoarhiv.App.csproj -c Release -r win-x64 --self-contained true -p:EnableWindowsTargeting=true -p:PublishSingleFile=false -p:PublishTrimmed=false -o /tmp/fotoarhiv-cross-publish
```

Кросс-публикация проверяет упаковку Windows runtime и зависимостей, но не их исполнение.
Windows ZIP намеренно не создан: требуется подтверждение Windows runner и запуска.
В CI выбран publish папкой: это сохраняет SQLite native DLL и остальные зависимости
рядом с программой, без распаковки single-file при запуске. Дефект single-file не заявляется;
это разрешённый заданием вариант доставки. Архивируется весь publish целиком.

## Изменения по файлам

- `src/Fotoarhiv.Core/PhotoScanner.cs`: распаковка nullable GeoLocation, сохранение валидной точки 0/0;
  отмена перед/после обхода; подсчёт недоступных источников/ошибок обхода без логирования путей/GPS.
- `src/Fotoarhiv.Core/DuplicateFinder.cs`: проверка размера/времени даже перед использованием
  кешированного SHA-256, сброс устаревшего хеша и при ошибке чтения; отмена и при пустом наборе.
- `src/Fotoarhiv.Core/CatalogStore.cs`: отключён ненужный пул единственного долгоживущего соединения,
  чтобы Dispose освобождал файловые дескрипторы SQLite. На Windows это дополнительно проверяет тест.
- `src/Fotoarhiv.App/Fotoarhiv.App.csproj`: явные импорты вместо конфликтующих глобальных импортов
  Windows Forms; версия 0.2.1, зависимости не заменялись.
- `src/Fotoarhiv.App/MainWindow.xaml.cs`: импорт System.IO, поиск дублей в рабочем потоке;
  защита продолжений после закрытия окна; очистка устаревших групп при обновлении;
  восстановление отображения после отмены; загрузка GPS-списка из сохранённого каталога;
  сообщение о неполном сканировании; обработка ошибок доступа/формата миниатюр.
- `src/Fotoarhiv.App/MainWindow.xaml`: имя кнопки для блокировки во время сканирования,
  уточнение передачи GPS OpenStreetMap, версия; дизайн сохранён.
- `tests/Fotoarhiv.Tests/P0Tests.cs`: 14 новых тестов, искусственные BMP/TIFF создаются локально;
  исходные 4 теста сохранены. Реальные фотографии не использовались.
- `tests/windows_smoke.py`: CI-проверка появления главного окна, таблиц SQLite и нормального
  закрытия опубликованного exe; при сбое завершает только созданный ею тестовый процесс.

  Используется bash на runner; VBS/PS1/CMD-запускателей нет. Python-скрипт не входит в publish.

## Что покрыто тестами

18 тестов: неразрушающая индексация; одинаковые байты под разными именами;
равные размеры с разным содержимым (также настоящие BMP); повторный обход и сохранение хеша;
обновление хеша изменённого файла; отказ от устаревшего кеша без предварительного сканирования;
валидное изображение без EXIF и помеченная файловая дата; EXIF-дата/GPS искусственного TIFF;
валидные координаты 0/0; обход вложенных/пересекающихся источников;
сохранность байтов, времени записи/создания после сканирования и хеширования;
постоянство SQLite/источников/метаданных/хешей; сохранение записей недоступных файлов;
сообщение о недоступной папке; отмена до начала и во время обхода;
обработка эксклюзивно заблокированного файла; освобождение файла БД после Dispose.
Это результаты Linux, а не подтверждение работы Windows/NTFS.

## Не проверено и ограничения

- CI не запускался: нет прав записи GitHub и доступного Windows runner в этой сессии.
  Синтаксическая проверка Python не заменяет выполнение Windows smoke.
- Ручная проверка выбора нескольких источников, поиска/года/страниц, отмены из GUI,
  повторного запуска и физического отключения диска не выполнена. Ошибки NTFS ACL
  не эмулировались; тест блокировки файла не заменяет проверку отказа доступа NTFS.
- Автоматическая проверка окна в CI охватывает только запуск/SQLite/закрытие,
  а не полный пользовательский сценарий. windows-latest — не обязательно Windows 11.
- При добавлении одной папки сканируется вся библиотека. Окно выбора допускает одну папку
  за действие; несколько источников добавляются последовательно, как в исходном проекте.
- Синхронные операции SQLite и декодирование до 72 миниатюр всё ещё могут задерживать GUI
  на медленных носителях/очень больших библиотеках. Производительность не измерялась.
- SHA-256 кеш инвалидируется по размеру и времени записи. Подмена с сохранением обоих
  признаков и внешнее изменение уже после проверки остаются ограничениями этой модели.
- Последний доступ может обновлять сама ОС при чтении; он не проверялся. Приложение
  не записывает в исходные фото и не меняет их время записи/создания.
- EXIF без часового пояса не превращается в придуманное UTC. Для неподдерживаемых/повреждённых
  метаданных используется помеченная дата файла; полнота RAW/HEIC зависит от библиотек/кодеков.
- «Собрать архив» остаётся честной заглушкой. Нет удаления, переноса, копирования архива,
  визуального сравнения или встроенной карты. Только явное открытие GPS в браузере.
- Проверок подписи/SmartScreen/антивируса нет. Подпись не добавлялась, обход защиты не предлагался.

## Следующий шаг без терминала (5 действий)

1. Распакуйте `Fotoarhiv_SOURCE_v0_2_1.zip`. Сохраните папки `.github`, `src`, `tests`, `tasks`.
2. Владелец репозитория переносит файлы через GitHub Desktop в main/master и публикует изменения;
   ChatGPT с доступом только для чтения сделать это не может.
3. Во вкладке Actions откройте **Build Fotoarhiv Windows x64** и дождитесь зелёного результата
   всех этапов, включая проверку окна. При ошибке сохраните журнал и TRX для исправления.
4. Только после успеха скачайте **Fotoarhiv-Windows-x64-0.2.1-TEST**, распакуйте артефакт и
   вложенный ZIP, оставив все файлы publish вместе. Запустите `Fotoarhiv.exe` на Windows 11 x64,
   учитывая предупреждения защиты без её отключения.
5. На небольшой тестовой копии данных проверьте добавление двух источников и подпапок,
   повторный запуск, EXIF/файловую дату, GPS, дубли, поиск, год, страницы, отмену,
   недоступный диск и неизменность оригиналов. До этого не считать P0 закрытым.

Полный исходный ZIP включает данный отчёт и фактические логи. Папки bin/obj, локальная .git,
SDK, временный publish и настоящие пользовательские фотографии в архив не включены.
