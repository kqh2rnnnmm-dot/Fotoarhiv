# Фотоархив 0.2.2 — перенос утверждённого интерфейса

Изменён существующий WPF-проект, без WebView, новых NuGet-зависимостей и переписывания ядра. Эталон — исходный HTML в `UI_REFERENCE/` и четыре оригинальных PNG. Полный P0 остаётся открыт до проверки персональных Windows 10/11.

## Реализовано

Белые меню и топбар, фирменное `фотоархив.`, палитра #F6F7F9 / #1A2636 / #3368F0, навигация из пяти разделов, четыре карточки реальных показателей, фильтры годов и месячная хронология. Сетка имеет 5/4/3 колонки, скругления и нижний градиент. Поиск обещает только имя/путь. Непроверенное число повторов показано как «—».

Данные фотографии открываются справа: настоящее превью, имя, EXIF или помеченная файловая дата, размеры, разрешение из заголовка изображения, исходная папка, полный путь, GPS и доступность. Закрытие крестиком/Escape, возврат фокуса. Метаданные переносятся по ширине панели. Четыре фоновых декодера уменьшают превью до 512 px по большей стороне; страница ограничена 72 снимками, карточки повторов — 12 группами и тремя превью на группу. Это ограничение объёма UI, а не измеренная производительность на сотнях тысяч файлов.

Повторы показывают реальные группы SHA-256 и превью, сравнение перечисляет настоящие пути. «Разные версии»/«Похожие кадры» отключены. Источники показывают подлинные папки, число известных записей и доступность. Карта — честная заглушка с действующим списком GPS и предупреждением перед явным открытием OpenStreetMap. Альбомы — пустое состояние. Окно архива воспроизводит композицию эталона, но копирование, перемещение и план отключены; фиктивная структура не рассчитывается.

Сканирование, SQLite, EXIF/GPS, SHA-256 и транзакционное сохранение оставлены существующими. Все пять файлов `src/Fotoarhiv.Core/` совпали по SHA-256 с исходной v0.2.1: `verification/task003/core-baseline.json`, `core-unchanged.json`. Путь базы прежний: `%LOCALAPPDATA%\Fotoarhiv\catalog.sqlite`. В пользовательский каталог тестовые изображения автоматически не добавляются.

## Подлинность снимков и сравнение

`screenshots/` содержит исходные PNG захвата клиентской области настоящего опубликованного WPF exe на Windows desktop. Отдельный снимок включает нативную рамку. Источник и точные размеры каждого снимка записаны в `screenshots/gui.json`. Изображения для теста искусственные, генерируются только Python-сценарием в собственной временной папке runner, затем сканируются через настоящий системный диалог; каталог не заполняется SQL.

`verification/task003/reference-html/` содержит отдельно визуализированный исходный HTML для сравнения; эти изображения не выдаются за WPF. Четыре входных PNG в `UI_REFERENCE/` сохранены побайтно. Исходный тёмный интерфейс до переноса зафиксирован как FAIL в `00-before-visual-check.json`, перечень расхождений — `UI_GAP_ANALYSIS_RU.md`. До добавления модели новые C#-тесты не компилировались; лог `01-presentation-before.log` сохранён. Итоговое сравнение не является заявлением о пиксельной идентичности.

Оставшиеся визуальные различия:

- В ленте другие изображения, числа и месяцы: это реальные записи искусственного набора. Города из демонстрационного макета не переносятся, подпись содержит только известную дату, при fallback — «Дата файла».
- Вместо нарисованной карты/демонстрационных городов показана предусмотренная заданием честная заглушка; справа реальные GPS без геокодинга.
- Количество и состав групп повторов определяются настоящим SHA-256. Нет выдуманного «лучшего кадра», похожих фотографий и рекомендаций удаления.
- Источники имеют реальные имена и пути; в окне архива нет демонстрационных назначений, объёмов или готового плана. Неактивные действия имеют видимое состояние «В разработке».
- Сохранены служебная нижняя строка состояния, обновление/отмена и пагинация существующего приложения. Рамка окна, системный диалог папок и растеризация шрифта принадлежат Windows/WPF.
- В узком окне меню и число колонок адаптируются; при недостатке высоты модальное содержимое прокручивается. Визуальный результат проверен в перечисленных клиентских размерах; реальные 125%/150% требуют отдельного системного прогона.

## Ограничения Windows 10/11

Основная ОС пользователя — Windows 10 x64; редакция и сборка неизвестны. Добавлен manifest Windows 10/11, `asInvoker`, PerMonitorV2/PerMonitor; нет Windows 11-only оформления. Существующий стек .NET 10 сохранён.

Фактический запуск на Windows 10 и Windows 11 — **NOT RUN**: доступен только Windows Server 2025. Совместимость с конкретным ПК пользователя не подтверждена. На дату проверки официальная матрица .NET 10 перечисляет поддерживаемые Windows 10 Enterprise/IoT LTSC-выпуски; обычная Windows 10 Home/Pro 22H2 в ней отсутствует. Это ограничение официальной поддержки runtime, а не доказательство отказа запуска. Self-contained ZIP включает .NET, но не отменяет требования ОС. Источник: https://github.com/dotnet/core/blob/main/release-notes/10.0/supported-os.md ; локальная копия `verification/task003/dotnet10-supported-os.md`.

Не проверены физическое отключение диска, NTFS ACL, запуск браузера из GPS, все кодеки RAW/HEIC и реальные системные DPI 125%/150%. Проверка уменьшенного рабочего пространства не заменяет DPI. Офлайн-превью не кешируются. Хеш-кеш по-прежнему полагается на размер/время изменения; подмена с сохранением обоих признаков — существующее ограничение. EXIF без часового пояса не объявляется UTC.

Архив — тестовая неподписанная сборка. В поставке нет VBS/PS1/CMD/BAT-запускателей; настройки защиты не изменяются. Подпись/отсутствие предупреждений на ПК не проверялись.

## Воспроизводимые команды Windows CI

```text
dotnet restore Fotoarhiv.slnx
dotnet build Fotoarhiv.slnx -c Release --no-restore
dotnet test tests/Fotoarhiv.Tests/Fotoarhiv.Tests.csproj -c Release --no-build --logger "trx;LogFileName=windows-tests.trx" --results-directory TestResults
dotnet publish src/Fotoarhiv.App/Fotoarhiv.App.csproj -c Release -r win-x64 --self-contained true -p:PublishSingleFile=false -p:PublishTrimmed=false -o publish
python tests/windows_smoke.py publish/Fotoarhiv.exe
python tests/windows_gui.py publish/Fotoarhiv.exe TestResults/gui
```

Их вызывает `tests/windows_ci.py`, сохраняя коды возврата, время, commit и run URL. ZIP создаётся только после всех обязательных PASS; доказательства сохраняются и при FAIL. CI-скрипт отказывается работать с существующим каталогом; GUI создаёт собственный временный набор. Имитация отсутствия использует только созданную самим тестом папку; пользовательские фотографии не перемещаются. Проверка EXIF/дублей и сканирование идут через настоящий exe, каталог не предзаполняется SQL.

- 41406729435 — новая проверка искала невидимую карточку показателя на странице «Источники» и получила ElementNotFoundError. Сценарий исправлен переходом в «Фотографии», требование «—» сохранено.

После сравнения первого настоящего снимка исправлены ширина/перенос метаданных, резерв под скроллбар и высота заголовка месяца. Скриншоты не ретушировались. Итоговое сравнение палитры — `visual-comparison.json`; первая строка фото в WPF примерно на 2 px ниже PNG, пиксельная идентичность не заявляется.
